# v0.28.0 — One view across repositories, still one local command

Released 2026-11-25.

The last gap I could name was the team view: `capability list` scanned a single
workspace. Closing it as a hosted service would have contradicted the product's
positioning — local, offline, no control plane — so it is closed as a local
command over files.

## Highlights

- **`capability list --root A --root B`**, or **`--index repos.json`**:

  ```json
  {"roots": ["api", "worker", "services/billing"]}
  ```

- Index paths resolve relative to the index file.
- With several roots the table gains a `repo` column, and every critical risk is
  prefixed with its repository.
- Duplicate roots count once; `--strict` aggregates across all of them and exits
  `1` if any capability anywhere has a critical risk.
- A broken index is an error (`2`), not an empty report.
- **Unverified stays unverified**: without the owner or receipt key, an approval
  that requires one is reported as invalid rather than assumed good. The team view
  needs the keys to tell you the truth.

## Evidence

- 653 tests, lint clean, CI on Python 3.10–3.13, seven required checks.
- Ran against two synthetic repositories — one passing, one failing — through an
  index file: the table named the failing one, and `--strict` exited `1`.

## Where the nine deployment gaps now stand

| gap | mechanism |
|---|---|
| acceptance criteria are unclear | derived from the repository (`init`, `propose`), bound to tests by the mutation oracle |
| the world is not observable | the Stop hook writes runtime evidence; session ↔ decision are cross-checked |
| no cheap authoritative oracle | thirteen primitives, an inference engine, a versioned registry |
| actions are irreversible | dry-run, sandbox, compensation drill, rollback check, distribution canary |
| testimony is not evidence | provenance rules, Ed25519, key ids, revocation |
| no owner, escalation, or audit | approvals, waivers, trail, receipts, status, registry |
| verification costs more than it is worth | stage budgets, cost in evidence, `utility` |
| long chains accumulate error | stages chained to commits, stale detection, linked evidence |
| it does not fit existing tools | Action, hooks, importers, `init --ci --hook` |

What remains is not a missing mechanism: it is that no real deployment has run
this yet.
