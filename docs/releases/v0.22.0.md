# v0.22.0 — The gate may not bless a weak configuration

Released 2026-11-25.

Running the first-ten-minutes path against the product found it blessing a
configuration that checked almost nothing. This release fixes that, and the
release workflow of this repository is now gated by a policy that cannot be
weakened silently.

## Highlights

- **A policy may not permit what it cannot justify.** `validate` refuses a stage
  that sets `allow_deploy` without an approval oracle (or `manifest_approval`)
  and rollback evidence with a named rollback oracle. It refuses a stage that
  allows `allow_merge` without an approval when the manifest declares `merge`
  irreversible.

  The prompt was concrete: `capability init` wrote a `production` policy with
  `allow_merge: true, allow_deploy: true`, no approval, and no rollback. A new
  user could run the gate and be told `deploy allowed: yes`.

- **The onboarding draft permits nothing.** Every stage starts locked;
  `init` prints what to add to unlock merge and deploy. Promotion is the owner's
  decision, not a default.

## Evidence

- 583 tests, lint clean, CI on Python 3.10–3.13, seven required checks.
- New tests: deploy without approval, without rollback evidence, without a named
  rollback oracle, a justified policy, `manifest_approval` counting as an
  approval, merge declared irreversible, merge not declared irreversible, the
  generated draft, every example, and the self capability.
- The examples and the self capability already carried the evidence their
  policies claimed; test fixtures that did not were corrected.

## Known limits

- The rule is structural: it checks that an approval and a rollback are
  *declared*, not that they are any good. `capability diff` and the assurance gap
  report judge the substance.
- A capability that declares no criteria still passes a stage that requires only
  oracles. The status card shows `0/0` criteria; it does not refuse.
- The semantic gap, canary traffic control, and the sandbox are unchanged.

## Upgrade

```bash
pip install --upgrade assaystone==0.22.0
pip install "assaystone[crypto]==0.22.0"   # optional Ed25519
```

Existing manifests that allowed deploy without an approval or rollback now fail
`validate`. That is the intended change: add the approval and the rollback, or
stop allowing the deploy.

For the GitHub Action, pin `yellowsand1/assaystone@v0.22.0`.
