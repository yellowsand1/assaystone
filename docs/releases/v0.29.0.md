# v0.29.0 — The loop is something a reader can run

Released 2026-11-25.

Every claim in this project was verified by its author, in prose. That is the
weakness the product criticises. `docs/trial.md` is now generated by
`scripts/trial.py` and diffed in CI, so the evidence cannot drift from the code.

## Highlights

- **`docs/trial.md` / `make trial`.** A small service is built, inspected, and
  walked through a change: the gate refuses it (six of six mutants survived),
  the test is added, the decision is written to a trail and signed into a
  receipt, and the card says what is still unresolved.
- **`tests.integrity` is semantic.** It failed on any change under a test prefix,
  which made "the agent added a test" a defect. Now: a deleted test file, a
  removed test, or fewer assertions fails; a rewritten test body escalates
  (counts cannot tell whether it still asserts the same thing); adding tests is
  fine.
- **`diff.ci_surface` allows the gate's own workflow** to be added — the draft
  writes it, and the next gate used to flag it as a CI bypass.

## Evidence

- 653 tests, lint clean, CI on Python 3.10–3.13, seven required checks.
- The trial is reproducible: timestamps, content hashes, signatures, and short
  commit ids are normalised in the output, and CI diffs the regenerated file.
- The self-release itself runs the drill and the production gate before
  publishing.

## Known limits

- The trial uses a small synthetic service. It shows the mechanism, not a real
  deployment.
- The mutation oracle shows the change is covered; it cannot show the test
  asserts the right thing.
- Canary compares two samples of one metric; it does not slice real traffic.
