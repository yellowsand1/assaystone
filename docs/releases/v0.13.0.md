# v0.13.0 — From one repository to a set of capabilities

Released 2026-11-25.

0.12.0 made exceptions auditable. 0.13.0 removes the setup friction and gives a
team one view across capabilities.

## Highlights

- **One-command onboarding.** `capability init --ci --hook` writes the draft
  manifest, a runnable GitHub Actions gate (pinned install, shadow gate, trail
  verification, evidence upload, and a commented receipt block), and
  `.assaystone/hook.json` for the Claude Code Stop gate. The workflow runs on the
  first push without a secret; receipts and owner approval stay opt-in.
- **The capability registry.** A capability is a `.assaystone/` directory with
  its manifest and sidecars (`trail.jsonl`, `receipt.json`, approval, waivers).
  `capability list --root .` prints one row per capability: owner, risk,
  lifecycle, coverage, last outcome per stage, approval, receipt, and critical
  risk count. `--strict` exits `1` on any critical risk; `--json` returns the
  same data.
- **The self-gate uses the convention.** Its trail and receipt are
  `.assaystone/trail.jsonl` and `.assaystone/receipt.json`, and CI runs the
  strict registry after writing them.

## Evidence

- 476 tests, lint clean, CI on Python 3.10–3.13.
- The self-gate runs the strict registry against its own evidence on every push
  and PR.
- The lifecycle case study, the two real-agent runs, and the MCP/MySQL validation
  remain the behavioral evidence.

## Known limits

- The registry scans the local workspace; it is not a hosted cross-repository
  service.
- It is read-only. It does not approve, waive, or merge.
- `capability init --ci` leaves the toolchain setup and secrets as comments for a
  reason: the generated workflow should run first, then be hardened.
- Production and incident are still not exercised on Assaystone's own release.
  The self-gate is `shadow`; releases are not yet gated with a production policy,
  owner approval, or a release receipt.
- The HMAC trust model, approvals without expiry, the semantic gap, and the
  fixture SQL domain remain as stated.

```bash
pip install --upgrade assaystone==0.13.0
```
