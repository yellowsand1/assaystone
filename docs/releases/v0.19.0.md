# v0.19.0 — Show the owner what they are re-approving

Released 2026-11-25.

An owner approval binds a manifest digest, so every edit forces a review. 0.19.0
gives the reviewer the one view that matters: what the change removed, softened,
or added.

## Highlights

- **`capability diff`.** Compare two manifest versions as a reviewer reads them:
  criteria added, removed, and changed; oracle fingerprints; per-stage
  requirements, approvals, rollback, and chain; owner, risk, lifecycle, and the
  approval and waiver flags.
- **Weakening is flagged explicitly.** A removed criterion, oracle, or stage; a
  removed requirement, approval, or rollback; a lowered severity or risk — the
  diff says *this change removes or lowers assurance*. Additions and tightened
  requirements are shown but not flagged.
- **`--json`** returns the same structure for a CI summary or a review bot.
- **The diff decides nothing.** It is input to the owner's decision, and the
  digest is what the approval binds.

## Evidence

- 521 tests, lint clean, CI on Python 3.10–3.13, all seven checks required by
  branch protection.
- New tests cover identical manifests, each weakening class, a tightening change
  that must not be flagged, oracle fingerprint changes, policy additions and
  removals, owner/risk/approval changes, the CLI in text and JSON, and an invalid
  manifest.

## Known limits

- The diff is structural: it cannot tell whether a new criterion is *good*, only
  that it appeared.
- `weakened` is a heuristic over removals and severity/risk decreases. A
  restructured manifest can read as weakening when the intent is neutral; the
  owner still decides.
- The semantic gap and the reverse-apply rollback limit remain as stated.
