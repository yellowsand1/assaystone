# v0.17.0 — The product's own release is gated

Released 2026-11-25.

Every previous release was published after a shadow self-gate. 0.17.0 is the
first release the product stops before publishing: the tag runs `gate --stage
production`, and a failure prevents the build and the PyPI upload.

## Highlights

- **A production gate on this repository.** The self-manifest declares
  `production` with tests, lint, Failure Zoo freshness, and a rollback oracle
  that requires the release commit to reverse-apply.
- **The owner signs the criteria.** `manifest_approval: true`, with an Ed25519
  approval signed by a key whose private half is outside the repository. The
  public key and the approval are committed; CI and agents never see the private
  key.
- **The release job signs its own evidence.** Before building, it installs the
  package, verifies the owner approval with the committed public key, runs the
  production gate, signs an Ed25519 release receipt with a key held in the
  `ASSAYSTONE_RELEASE_KEY` GitHub secret, verifies it against the committed
  public key and `GITHUB_SHA`, and uploads `assaystone-release-evidence`.
- **Lifecycle-aware status and registry.** A future stage without evidence is
  information, not a current defect. `capability status` shows the stage gap;
  `capability list --strict` requires the current lifecycle stage and any
  recorded stage to pass.

## Evidence

- 490 tests, lint clean, CI on Python 3.10–3.13.
- Locally: the owner approval verified, the production gate passed with a
  release key, the Ed25519 receipt verified against the public key and commit,
  and the status card and strict registry reported no critical risk.
- The release workflow itself is the integration test: this tag runs it.

## Known limits

- The owner key represents this project's owner. It is not an external approval
  system, and there is no revocation or identity binding.
- The rollback check is a reverse-apply check on the release commit, not a
  deployed-system rollback.
- If the production gate fails, the release stops; the fix is a code or evidence
  change, not a bypass.
- The semantic gap and the fixture SQL domain remain as stated.

