# v0.34.0 — Calibrated acceptance

Released 2026-11-27.

v0.33.0 made the decision an artifact. This release makes the artifact tell you
what the decision is worth.

## Highlights

- **Every check carries its measurement.** In a certificate, each check records
  recall on the defect classes it *claims*, false-alarm rate on clean cases,
  adversarial recall, and the sample size behind the number, plus the digest of
  the profile used. A check with no data says `unmeasured`.
- **`assurance.calibration`.** Measured and unmeasured checks, the minimum
  recall, the maximum false-alarm rate, and the **calibration gap**: the share of
  deciding checks that have never been measured. The audit demo's own contract
  is 75% unmeasured; the product says so first.
- **`require_measured`: calibration as a gate.** A contract can require that a
  pass rest on at least one measured, independent check. A pass supported only by
  unmeasured instruments escalates with `calibration required`.
- **External profiles.** `--reliability profile.json` (repeatable on `check` and
  `verify`) merges a third-party profile per check. Each entry records its source
  and digest; malformed probabilities are rejected. Merging does not vouch for
  the numbers — it makes them checkable and cites them.
- **`prove --gaps`.** From a certificate directory or a contract, ranks the
  checks that decide most often and have no measurement. The gap becomes a list
  of cases to add.
- **Generate the profile yourself.** `assaystone prove --write-reliability
  profile.json` or `make reliability`; `docs/reliability.md` is generated from it
  and ships in the package, so certificates stay offline.
- **Pre-tool gate.** `assaystone hook claude-code-pre` decides a tool call before
  it executes from `.assaystone/policy.json` — denied tools, paths, shell
  patterns, and a workspace boundary — and exits 2 to block in `block` mode.
  Every decision is appended to `.assaystone/session.jsonl` as runtime-written
  evidence.
- **Audit follows the agent into its workspace.** Absolute tool paths determine
  the workspace root when it differs from the transcript's `cwd`; a partial
  replay reads files from the workspace, and a written test stays `added`.

## Breaking changes

- `hook install claude-code` now installs both `PreToolUse` and `Stop` hooks and
  writes a starter `.assaystone/policy.json`. Existing `Stop`-only settings are
  merged, not replaced.
- Contracts accept an optional `require_measured` (default `false`). Existing
  contracts are unchanged.
- Certificates and `RunResult` gain reliability and calibration fields. The
  certificate schema id stays `assaystone.certificate/1`; consumers that require
  exact keys should read the new ones.

## Evidence

- 734 tests, 5 skipped; ruff clean; CI on Python 3.10–3.13.
- A real Claude Code session (84 tool calls, 10 files) reconstructed and checked;
  see `docs/field-note-claude-code.md`.
- A real Flask snapshot: 68–98 ms per check, deleted test and CI edit caught;
  see `docs/field-note-flask.md`.
- The wheel ships `reliability.json`; a clean venv install produces a calibrated
  certificate offline.
- The repository's own production gate passes before publishing.

## Known limits

- 9 of 17 built-in checks have a measurement, most with `n = 1–2`. The corpus is
  a floor, and the certificate says so.
- External profiles are self-declared. The format makes them checkable; it does
  not make them true.
- The pre-tool policy is lexical. A shell redirect or a script's internal writes
  are not seen as paths; add a command pattern if you need one.
- Post-tool and pre-final gates are not in this release.
- No external user yet. P1 remains three external repositories, one published
  defect the tests missed, and one external contract.
