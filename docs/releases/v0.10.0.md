# v0.10.0 — The product gates itself

Released 2026-11-25.

0.9.0 closed the agent loop with a brief. 0.10.0 makes the decision
authentic and the criteria owned: signed gate receipts, owner approval of the
manifest digest, and Assaystone's own repository gated by its own plane.

## Highlights

- **Signed gate receipts.** `gate --receipt` writes an HMAC-SHA256 receipt bound
  to the commit, the manifest digest, the trail head, and every oracle digest.
  `receipt verify` checks it offline and fails on any changed field, wrong key,
  or a commit/manifest/outcome mismatch. The gate refuses to sign a broken trail
  and refuses a missing key.
- **Owner approval of the acceptance criteria.** `"manifest_approval": true`
  requires the owner to sign the manifest digest via `capability accept` with
  `ASSAYSTONE_OWNER_KEY`. The gate verifies capability, digest, and signature
  before any oracle. Missing, tampered, or stale approvals escalate.
- **Two keys, two powers.** The owner key defines acceptance; the receipt key
  records a decision. The docs say to keep them apart and out of the agent's
  environment.
- **Assaystone gates itself.** `.assaystone/capability.json` declares the
  repository's tests, lint, and Failure Zoo freshness. CI runs the gate, writes
  a trail, signs a receipt, verifies both against the checked-out commit, and
  uploads `assaystone-self-gate`.
- **The GitHub Action** gains `receipt`, `receipt-key-env`, `manifest-approval`,
  and `owner-key-env`.

## Evidence

- 446 tests, lint clean, CI on Python 3.10–3.13.
- The self-gate passes locally in 20.97 s; CI uploads the trail and receipt.
- The lifecycle case study and the two real-agent runs remain the behavioral
  evidence from 0.9.0.

## Known limits

- HMAC is symmetric in both keys. A receipt proves the signer held the key, not
  public verifiability.
- Approvals have no expiry; they are valid while the digest is unchanged.
- The self-gate is `shadow` only, uses a job-level test receipt key, and does not
  set `manifest_approval` — the owner key must not live in CI. Branch protection
  must make the self-gate required; the repository does not claim that is
  configured.
- The semantic gap, the conflict-without-waiver gap, and the fixture SQL domain
  remain.

## Upgrade

```bash
pip install --upgrade assaystone==0.10.0
```

For the GitHub Action, pin `yellowsand1/assaystone@v0.10.0`.
