# v0.27.0 — A canary is a statistic, not a request

Released 2026-11-25.

The canary gap looked environmental: no traffic, no canary. That was wrong. The
question a canary asks is statistical — *is the candidate worse, or is this
noise?* — and it can be answered with repeated measurements, offline or against
two live endpoints.

## Highlights

- **`canary` oracle (thirteenth primitive).** Samples the incumbent and the
  candidate, bootstraps an interval for the difference with a fixed seed, and
  fails only when the relative change exceeds the limit **and** the interval
  excludes zero.

  ```text
  the candidate is +30.0% worse than the baseline (limit +10.0%) and the 95%
  interval for the difference is [26.1, 33.7], which excludes zero
  ```

- **Noise does not fail.** A change over the limit with an interval that includes
  zero is reported as *not a regression yet*, with the evidence.
- **Fewer than five usable measurements per side escalates.** At that size a
  canary cannot distinguish a regression from noise, and saying otherwise would
  be the dishonesty the product exists to remove.
- **Reproducible.** The bootstrap uses a fixed seed: the same inputs give the
  same verdict. A gate that flipped on a random draw would be worse than none.
- Either side can be any oracle that yields a number (`http`, `sql`, `command`).

## Evidence

- 645 tests, lint clean, CI on Python 3.10–3.13, seven required checks.
- Local servers with Gaussian noise: identical sides pass, a `+30%` candidate
  fails with an interval excluding zero, `±40` noise passes.

## Known limits

- Two samples of one metric. It does not slice traffic, attribute failures to
  users, or replace a canary with real traffic — it makes the decision arithmetic
  explicit so the same code runs against recorded baselines, a staging pair, or
  production.
- The bootstrap is an approximation at small n; that is why five is the floor.
- The semantic and organisational limits in `docs/plane.md` are unchanged.
