# v0.18.0 — Retire a key, enforce the gate

Released 2026-11-25.

0.17.0 gated the product's own release. 0.18.0 makes the trust model operable and
the gate unbypassable, and fixes a documentation claim that had drifted from
reality.

## Highlights

- **Key revocation.** `capability.revocations.json` lists key ids that must no
  longer be trusted, each with a reason. The gate checks owner approvals, waiver
  entries, and receipt key ids against it and **escalates** on a match, naming
  the artifact and the reason. A revoked key makes a past decision unable to
  stand, not false. An unreadable list escalates; a list without reasons is
  rejected. The status card and registry report revoked artifacts as residual
  risk.
- **`main` is protected.** The branch requires a pull request and the seven CI
  checks, with administrators included and force pushes and deletions disabled.
  A direct push is rejected by the remote. This release was merged through the
  gate, not pushed to it.
- **The changelog is checked.** `tests/test_release_consistency.py` asserts that
  `pyproject.toml`, `__version__`, the changelog heading, the release notes file,
  `ACTION_REF`, and the README pins all agree. It exists because they did not:
  the old release-prep edit matched a fixed string, stopped matching once the
  Unreleased section had content, and the changelog skipped eight releases. The
  missing sections were rebuilt from the release notes.
- **`scripts/release_prep.py`** replaces the fragile edits. It performs every
  edit or none, and refuses to run without a matching release-notes file.

## Evidence

- 510 tests, lint clean, CI on Python 3.10–3.13.
- Observed rejection: a direct push of a throwaway commit to `main` returns
  `protected branch hook declined`.
- Revocation tests cover a valid pass, a revoked owner key, an unreadable list,
  an unrelated revoked key, a missing reason, the trail and receipt record, the
  status card, and the CLI.

## Known limits

- Revocation is a committed list, not a distribution service; its integrity comes
  from repository review. Commit it before or with the key rotation.
- There is no key expiry and no identity binding behind a key.
- The release gate's rollback check is a reverse-apply check on the release
  commit, not a deployed-system rollback.
- Branch protection is a repository setting; a fork or a mirror can have
  different rules, and the evidence artifact is what a reviewer should check.
