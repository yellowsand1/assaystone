# v0.13.1 — Incident trial and a strictness fix

Released 2026-11-25.

A patch release for a defect the production/incident trial found, plus the trial
write-up.

## Fix

`capability list --strict` treated a criterion gated only at a later lifecycle
stage as a critical defect at the current one. A capability at `shadow` is not
expected to gate production criteria.

Strict mode now requires every declared stage to have a passing decision and
every critical criterion to be gated somewhere. The per-stage gap remains on the
status card as information.

## Trial

The case study now includes the incident pass on the real Maven module: canary →
production → a caught API break → working-tree restore → an incident gate that
requires API parity, a clean worktree, a reverse-applicable commit, and two
signed approvals. The trail, receipt, status card, and strict portfolio were
verified. The write-up states the limit: this is a working-tree rollback, not a
production rollback.

See [case-study-lifecycle.md](../case-study-lifecycle.md#incident-a-verified-rollback).

## Evidence

- 477 tests, lint clean, CI on Python 3.10–3.13.
- The trial re-ran clean after the fix: strict portfolio 0 critical, 6 trail
  entries, a valid receipt.
