# v0.16.0 — Name the key that signed

Released 2026-11-25.

0.15.0 split the owner from CI with Ed25519. 0.16.0 makes each Ed25519 artifact
state which key signed it, so a substitution is detectable and rotation has a
handle.

## Highlights

- **Key ids.** Approvals, waivers, and receipts carry the SHA-256 fingerprint of
  the signing public key as `key_id`, inside the signed body. Verification
  rejects a public key whose fingerprint does not match, even when the signature
  itself is valid.
- **`key fingerprint`.** `key fingerprint --public owner.pub` prints the id;
  `key generate` shows it as well.
- **Rotation is visible.** Publish a new key id; old artifacts keep the old one.
  There is still no revocation list or identity system; the docs state that.
- **HMAC is unchanged.** No key id is present on HMAC artifacts, and the core
  remains dependency-free.

## Evidence

- 488 tests, lint clean, CI on Python 3.10–3.13.
- New tests cover fingerprint stability and distinction, key ids on approvals,
  waivers, and receipts, and a key-id mismatch after re-signing with the same
  private key.
- The trust model is now: owner private key → owner public key + key id; gate
  private key → receipt public key + key id; a verifier needs only public keys.

## Known limits

- No revocation list, no key expiry, and no identity binding. A leaked private
  key cannot be marked untrusted by the tool yet.
- HMAC remains for single-team pipelines.
- The semantic gap, the working-tree rollback limit, and the fixture SQL domain
  remain as stated.

## Upgrade

```bash
pip install --upgrade assaystone==0.16.0
pip install "assaystone[crypto]==0.16.0"   # optional Ed25519
```

For the GitHub Action, pin `yellowsand1/assaystone@v0.16.0`.
