# v0.8.0 — Gate a capability from the GitHub Action

Released 2026-11-25.

0.7.0 chained the lifecycle stages. 0.8.0 puts the gate where CI already runs:
one `uses:` step, the same manifest, the same trail.

## Highlights

- **Manifest mode in the Action.** Pass `manifest` and `stage` (plus optional
  `root`, `audit`, `actor`, `strict`) instead of `contract` and `traces`. The
  action writes the oracle table to the job summary, sets `verdict` and
  `findings` outputs, emits `::error::` or `::warning::`, and exits non-zero on
  `fail` or `escalate`.
- **The summary includes the assurance gap**, so a reviewer sees what the stage
  did not check.
- **The action is exercised in CI.** A job runs it against the pricing fixture
  with `install: "."`, checks the outputs, and verifies the produced trail.
- **The verify mode is unchanged.** `contract` + `traces` still work; passing
  both modes is an error.

## Operational note

When a stage declares `after`, carry the same trail artifact from the earlier
stage. The action writes the trail you pass in `audit`; it does not create a
new history for you.

## Evidence

- 422 tests, lint clean, CI on Python 3.10–3.13.
- The `action-gate` CI job runs the composite action end to end.
- `action.yml` and `ci.yml` parse as YAML; the summary script has unit tests.

## Known limits

- The action installs Assaystone from its ref by default; set `install` to a
  released version when you need a reproducible toolchain.
- A GitHub rerun of a failed Pages-style deployment is unrelated; this action
  is not affected.
- The 0.7.0 and 0.6.0 limits remain: the trail proves integrity, not
  authenticity; unsigned approvals are files; semantic escapes are still 0%
  resistance; unsupported languages escalate.

## Upgrade

```bash
pip install --upgrade assaystone==0.8.0
```

For the GitHub Action, pin `yellowsand1/assaystone@v0.8.0`.
