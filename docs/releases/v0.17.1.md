# v0.17.1 — Verify against the tag you mean

Released 2026-11-25.

0.17.0 was the first release gated at production. Verifying that release's
evidence by hand found two small defects in the reporting; this patch fixes them.

## Fix

- **`receipt verify --commit`** now accepts a ref and resolves an annotated tag to
  its commit. `git rev-parse v0.17.0` returns the tag object, not the commit the
  receipt signs, so the check failed with a confusing mismatch.
- **The receipt report** names the scheme: an ed25519 receipt shows its key id
  and says the public key verifies it, instead of printing the HMAC note.

## Evidence from the first gated release

`v0.17.0` ran the production gate before building:

- the committed owner approval verified against the committed public key
  (`scheme=ed25519`, `key_id=sha256:4588390fcd48b067`);
- tests, lint, the Failure Zoo drift check, and the rollback oracle passed;
- the release receipt was signed with the key in `ASSAYSTONE_RELEASE_KEY`
  (`key_id=sha256:6d72961404625d7a`) and verified against the commit;
- the trail and receipt are downloadable as `assaystone-release-evidence`.

Re-verify it with this version:

```bash
assaystone receipt verify release-receipt.json \
  --public-key .assaystone/release.pub --commit v0.17.0 --outcome pass
```
