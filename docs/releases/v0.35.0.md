# v0.35.0 — The four positions

Released 2026-11-27.

Verification usually happens at the end, when the work is already done. This
release puts the same policy and the same contract at four points in the
harness: before a call, after a call, before the stop, and after the session.

## Highlights

- **Pre-tool.** `assaystone hook claude-code-pre` decides one tool call from
  `.assaystone/policy.json` — denied tools, paths, shell patterns, and a
  workspace boundary — and exits 2 to block. Every decision is written to
  `.assaystone/session.jsonl` as runtime evidence.
- **Post-tool.** `assaystone hook claude-code-post` checks what the action
  produced: Python syntax after a write, and high-confidence secrets in the
  written content, the command, or the tool response. In `block` mode the defect
  is fed back to the model on the next step.
- **Pre-final.** With `gate` in `.assaystone/hook.json`, the Stop hook runs the
  contract on the working tree, writes the certificate to
  `.assaystone/certificates/`, and refuses the stop on a failure. A pass is
  silent but still certified; no changes skip; a broken contract fails open.
- **Post-episode.** The default Stop audit remains available when no contract
  gate is configured.
- **The reliability profile is a protocol schema.**
  `assaystone lab protocol --schemas DIR` now writes
  `reliability.schema.json`, so an external pack can validate its own
  measurements before shipping them. `hook install claude-code` installs the
  `PreToolUse`, `PostToolUse`, and `Stop` hooks.

## Evidence

- 747 tests, 5 skipped; ruff clean; CI on Python 3.10–3.13.
- A deleted test blocks the stop and writes a fail certificate; a clean change
  is silent and certified; no changes skip; a broken contract fails open.
- The wheel ships the reliability profile and the schemas; a clean venv install
  produces a calibrated certificate offline.
- The repository's own production gate passes before publishing.

## Known limits

- The post-tool gate is a correction loop, not a transaction: the action already
  happened.
- Command matching is lexical; a shell redirect or a script's internal writes are
  not seen as paths.
- `base: HEAD` at the stop compares uncommitted work. A session that commits its
  own work needs a different base; CI remains the authority.
- Spec coverage — turning a task description into checkable obligations — is not
  in this release.
- No external user yet. P1 remains three external repositories, one published
  defect the tests missed, and one external contract.
