# v0.26.0 — Do not judge a tree you have modified

Released 2026-11-25.

A gate that changes the repository it is judging is measuring something that no
longer exists. `--sandbox` runs the checks that touch the workspace in a
disposable copy.

## Highlights

- **`gate --sandbox`.** Workspace oracles — `command`, `file`, local `sql`,
  `shadow`, `verifier`, `runtime`, `drill`, `mutation` — run in a copy, so a seed,
  a migration, or a build does not touch the repository. Afterwards the real tree
  is untouched.
- **Only checks that reach outside use the real root**: `git` (repository
  metadata), `http` (an endpoint), `human` (an approval queue), and `sql` with
  `dsn_env`.
- **`sandbox: true` is recorded** in the result and the trail: "passed in a copy"
  is different evidence from "passed here".
- **`--dry-run` and `--sandbox` are mutually exclusive** — a dry run skips
  mutating oracles, so there is nothing to protect.

The first version of this sandboxed only `mutates: true` oracles and broke the
seed → ledger pair: the query ran on the real tree while the seed ran in the copy.
The split is by scope, not by mutation.

## Evidence

- 632 tests, lint clean, CI on Python 3.10–3.13, seven required checks.
- End to end on the pricing project: `ledger.db` is never created under
  `--sandbox`, and is created without it.

## Known limits

- The copy excludes `.git`, heavy build directories, and virtualenvs; a check
  that needs them must be declared external.
- A sandboxed run does not prove the same oracles pass in the real tree; it
  proves the workspace checks do, without side effects.
- Canary compares one measurement per run, not a distribution.
- The semantic and organisational limits in `docs/plane.md` are unchanged.
