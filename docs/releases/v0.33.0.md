# v0.33.0 — The certificate is the product

Released 2026-11-27.

The project had a good kernel and no single thing a reviewer could hold. This
release makes the decision itself the artifact, gives it one entry point, and
cuts the surface to what a person can adopt in an afternoon.

## Highlights

- **`assaystone check` works on a live working tree.** `check --base
  origin/main` reconstructs the episode from git — the base ref, the working
  tree, and untracked files — materializes the base commit as a temporary
  worktree so the contract can run tests, and writes a certificate. No trace, no
  instrumentation, no API key, no network.
- **Certificate v1 (`assaystone.certificate/1`).** Hash-addressed and
  provenance-bound. `issued_at` and per-check timing are excluded from the id, so
  the same decision keeps the same id across machines. `certificate show` prints
  the decision, checks, assurance gap, coverage, and cost; `certificate verify`
  re-checks structure and content id offline.
- **The certificate reports the gap.** Declared defects, covered defects, and
  uncovered defects are separate fields. The audit demo is honest about its own
  contract: 9 of 10 declared defects covered, `regression` uncovered.
- **Five-command surface.** `audit`, `check`, `certificate`, `prove`, `hook`.
  Seventeen lifecycle and lab commands moved under `assaystone lab` and are
  frozen. Their old top-level names still resolve as aliases so existing CI does
  not break.
- **`prove` measures the checks themselves.** Recall on the labelled Failure Zoo
  and resistance to a contract-aware agent in one report, with thresholds and
  JSON.
- **The 60-second demo ends with the artifact.** `assaystone demo audit` now
  writes `audit-demo-session.certificate.json` and prints the command a third
  party runs to check it.
- **Release tooling stops lying.** `release_prep.py` strips the `No changes yet.`
  placeholder before writing a release section; twelve stale placeholders were
  removed from past sections.

## Breaking changes

- Lab and lifecycle commands moved under `assaystone lab`. Top-level aliases keep
  old invocations working, but `--help` now lists five product commands.
- The `check` verb is the new entry point for a worktree. `verify` remains as an
  alias for the trace-based path.

## Evidence

- 697 tests pass, 5 skipped; `unittest discover` reports 701 tests OK.
- Ruff clean on `assaystone`, `tests`, and `scripts`.
- CI on Python 3.10–3.13, seven required checks.
- All four demos run from an installed wheel; `check` is exercised against a real
  temporary git repository (deleted test fails, clean fix passes, no changes
  errors).
- The repository's own production gate passes locally with a clean `dist/`:
  tests, lint, Failure Zoo drift, rollback, and the verified-build drill.

## Known limits

- No external user yet. This release is the artifact and the entry point; the
  next milestone is three external repositories in CI, not more surface.
- The default checks are for code in a git repository.
- `tests.integrity` is path- and structure-based: it reports activity, not
  intent.
- The Failure Zoo corpus is a floor, not a population estimate.
- Harness pre-tool / post-tool gates and spec coverage are P2, after external
  proof. The lifecycle plane is frozen, not deleted.

## Upgrade

```bash
pip install --upgrade assaystone==0.33.0
```

For the GitHub Action, pin `yellowsand1/assaystone@v0.33.0`. The `check` mode
takes `base` and `certificate` inputs and uploads the certificate as an artifact.
