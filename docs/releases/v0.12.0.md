# v0.12.0 — Approved exceptions, not bypasses

Released 2026-11-25.

0.11.0 made the gate reach the agent. 0.12.0 handles the case that a strict gate
must not ignore: an owner may accept one named failure, for a reason and a
limited time, without turning the gate into a formality.

## Highlights

- **Owner-signed waivers.** A manifest with `"waivers": true` lets the owner sign
  a per-criterion exception with `capability waive`, bound to the current
  manifest digest, with a reason, an approver, and an expiry date.
- **The gate applies a waiver only when** the signature verifies under the owner
  key, the waiver has not expired, the manifest digest matches, the failing
  oracle returned `fail` (not `escalate`), and every criterion bound to that
  oracle is waived.
- **A waiver is residual risk, not a pass.** It is recorded in the trail, the
  receipt, and the status card with the approver and expiry. A missing owner key
  when a waiver is needed escalates.
- **The Action** gains a `waivers` input; the default path is next to the
  manifest.

## Evidence

- 466 tests, lint clean, CI on Python 3.10–3.13.
- The self-gate, the status card, the Stop hook, and the two real-agent runs
  remain the behavioral evidence from earlier releases.

## Known limits

- HMAC owner keys are symmetric; a verifier needs the key. The owner key must
  stay out of the agent's environment and out of CI.
- Waivers do not auto-renew and do not cover escalations. Expired waivers fail.
- The status card remains per capability; a cross-capability portfolio view is
  not in this release.
- The semantic gap and the fixture SQL domain remain as stated.

## Upgrade

```bash
pip install --upgrade assaystone==0.12.0
```
