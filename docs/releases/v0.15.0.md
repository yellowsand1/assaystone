# v0.15.0 — The owner's key stays with the owner

Released 2026-11-25.

0.14.0 made receipts publicly verifiable. 0.15.0 finishes the split: CI can
verify an owner approval or waiver without holding the owner's secret.

## Highlights

- **Ed25519 owner approvals and waivers.** `capability accept` and
  `capability waive` accept `--private-key-file`; the gate, `capability status`,
  and `capability list` verify with `--owner-public-key`.
- **Scheme per artifact.** Each approval and waiver signature carries its own
  prefix (`hmac-sha256:` or `ed25519:`), so a repository can migrate one signer
  at a time.
- **HMAC remains the default.** `cryptography` is an optional extra; the core
  stays dependency-free.
- **The Action** gains `owner-public-key`.

The trust model is now:

| decision | private key | verifier holds |
|---|---|---|
| acceptance criteria / exception | owner | owner public key |
| one gate decision | gate runner | receipt public key |
| third-party review | — | public keys |

## Evidence

- 487 tests, lint clean, CI on Python 3.10–3.13.
- Ed25519 approval, waiver, missing-key, wrong-key, and CLI paths are covered.
- HMAC tests are unchanged and pass.

## Known limits

- Keys have no identity, rotation, or revocation yet. The next step is a key id
  (fingerprint) in the signed body and a rotation story.
- HMAC remains for single-team pipelines.
- The semantic gap, the working-tree rollback limit, and the fixture SQL domain
  remain as stated.

## Upgrade

```bash
pip install --upgrade assaystone==0.15.0
pip install "assaystone[crypto]==0.15.0"   # optional Ed25519
```

For the GitHub Action, pin `yellowsand1/assaystone@v0.15.0`.
