# v0.31.0 — Carry out the next step instead of describing it

Released 2026-11-25.

`capability next` said what blocked the promotion. `--apply` does the part that
can be done mechanically, and refuses the part that cannot.

## Highlights

- **`capability next --apply`** adds the approval oracle, the missing stage
  policy, and the missing `require` entries, then refuses to write a manifest
  that would not validate.
- **It will not invent evidence.** A compensation command has to be a real
  command and an approval has to come from a person; those stay on the *still
  needs a person* list.
- **Applying makes an owner approval stale**, and the command says so.
- **The trial closes on itself**: blocker → apply → stage declared → re-validate,
  in `docs/trial.md`, which CI diffs.

## Evidence

- 670 tests, lint clean, CI on Python 3.10–3.13, seven required checks.
- `python scripts/trial.py --markdown | diff - docs/trial.md` passes.
- Applying twice changes nothing; an invalid result is refused before writing.

## Known limits

- "Ready" means nothing structural blocks the promotion; the gate still decides.
- The template policy uses the oracles the manifest already has. It is a
  starting point, not a considered policy.
- The semantic and organisational limits in `docs/plane.md` are unchanged.
