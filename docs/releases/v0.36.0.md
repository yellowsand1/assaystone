# v0.36.0 — The task is an artifact

Released 2026-11-27.

A contract says what "acceptable" means for a task type. The requirements of a
particular task usually live in a prompt and disappear with it. This release
makes them a checked artifact.

## Highlights

- **Task specs.** `.assaystone/spec.json` lists obligations with deterministic
  evidence rules: a changed path, a file that contains a string, a path that
  must not change, a file that must exist. Each obligation can be `all` or `any`,
  carries a severity, and says what to do when it cannot be decided.
- **`check --spec` and `verify --spec`.** The obligations compile into criteria
  with `source: "evidence"` and run with the contract. No model, no natural
  language parsing, fully offline.
- **Coverage in the certificate.** `assurance.spec` reports satisfied, violated,
  and unknown obligations plus a coverage ratio; `certificate show` prints
  `spec 3/3 obligations met`. The spec digest is in the contract block, so a
  different checklist is a different decision.
- **`spec.schema.json`** joins the protocol schemas. `protocol --schemas DIR`
  now writes contract, verifier, verdict, reliability, and spec schemas.
- **Pre-final uses the same contract**, so a spec is checked before the agent
  stops when a `gate` is configured.

## Evidence

- 756 tests, 5 skipped; ruff clean; CI on Python 3.10–3.13.
- A spec with a missing migration fails the check; the same spec without it
  passes and the certificate reports `3/3`.
- The wheel ships the spec schema and the reliability profile; a clean venv
  install runs the full path offline.
- The repository's own production gate passes before publishing.

## Known limits

- The spec does not parse natural language. A free-form ticket becomes checkable
  only when a person or a planning agent writes the obligations down.
- Globs use `fnmatch`; `*` crosses `/`. Be explicit.
- `path` and `absent` look at changed paths; `contains` and `exists` also read
  the baseline when nothing changed.
- It can check that a migration exists. It cannot check that the migration is
  correct; that is a contract check.
- No external user yet. P1 remains three external repositories, one published
  defect the tests missed, and one external contract.
