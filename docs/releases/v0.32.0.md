# v0.32.0 — Say what the environment owes the gate

Released 2026-11-25.

`capability next --apply` makes the manifest able to express a stage. Between
that and a gate that can pass there is a gap: the records the gate reads outside
the manifest. `capability prepare` names them.

## Highlights

- **Per required oracle**, it checks what the gate will read:
  - an approval record that exists, names the action, and is granted — and is
    signed when the oracle asks for a signature;
  - a drill record that exists and passed;
  - a session record the hook will write.
- **Every need names who acts** — `approver` or `operator` — and gives the
  command or the JSON shape. Nothing is created on the operator's behalf: an
  approval is a person's decision, and a drill is a claim about the world.
- **The trial ends with the human step**, right after the machine one:

  ```text
  7b. one command later, the stage is declared   → applied 3 change(s), ready
  7c. what a person still has to do              → [approver] approvals.json
                                                    does not exist; shape ...
  ```

## Evidence

- 680 tests, lint clean, CI on Python 3.10–3.13, seven required checks.
- `python scripts/trial.py --markdown | diff - docs/trial.md` passes.

## Known limits

- It reads the records, not the world: an approval file can still be written by
  anyone with access, which is why the `hmac_env` signing option exists.
- A drill record is machine-local; `prepare` cannot tell you whether a *remote*
  system was compensated.
- The semantic and organisational limits in `docs/plane.md` are unchanged.
